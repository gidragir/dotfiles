# 📐 Архитектурный план: Кроссплатформенная Shell-агностик экосистема

> **Целевые платформы:** Linux, Windows  
> **Целевые оболочки (Shells):** Zsh, PowerShell (`pwsh`), Nushell (`nu`)  
> **Базовый инструментарий:** Chezmoi, Nushell, Mise, Just  

---

## 📌 1. Архитектурный обзор и принцип разделения ответственности

Основная проблема попыток создания универсальных шелл-библиотек — смешение интерактивного контекста шелла (навигация, переменные окружения, буфер ввода) и автономной логики (скрипты, таски). 

Архитектура строго разделена на **3 изолированных уровня**:

```
┌────────────────────────────────────────────────────────────────────────┐
│  L1: Shell Frontend & Session State (Zsh / Pwsh / Nu)                  │
│  - Управление $PWD (cd, zoxide), переменные сессии, ZLE/PSReadLine     │
│  - Zero-latency алиасы (SSOT в Chezmoi -> нативная компиляция)        │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ делегирование вызовов в $PATH
┌───────────────────────────────────▼────────────────────────────────────┐
│  L2: Portable CLI Utilities & Logic Engine (Nushell)                  │
│  - Автономные CLI-утилиты (.nu) с типизацией, HTTP, JSON, FS           │
│  - Кроссплатформенность: единый код для Win32 API и POSIX syscalls    │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ оркестрация сценариев
┌───────────────────────────────────▼────────────────────────────────────┐
│  L3: Host Environment & Task Runner (Mise + Just)                      │
│  - mise: SSOT для версий тулчейна (nu, just, eza, fzf) и путей $PATH   │
│  - just: Оркестратор задач хоста с директивой `set shell := ["nu", "-c"]`│
└────────────────────────────────────────────────────────────────────────┘
```

## ⚙️ 2. Детальная спецификация уровней

### Уровень 1: Интерактивный фронтенд и SSOT-алиасы (Chezmoi)
Алиасы не запускаются через внешние процессы во избежание оверхеда (`fork/exec`). Они генерируются на этапе применения dotfiles (`chezmoi apply`).

* **Файл данных (Single Source of Truth):** `.chezmoidata/aliases.yaml`
  ```yaml
  aliases:
    ll:
      cmd: "eza -l --icons"
      args: true
    la:
      cmd: "eza -la --icons"
      args: true
    g:
      cmd: "git"
      args: true
    c:
      cmd: "clear"
      args: false
  ```

* **Шаблоны генерации нативных файлов:**
  * **Zsh** (`dot_config/zsh/aliases.zsh.tmpl`):
    ```gotemplate
    # Auto-generated by chezmoi. DO NOT EDIT.
    {{ range $name, $val := .aliases }}
    alias {{ $name }}='{{ $val.cmd }}'
    {{- end }}
    ```
  * **PowerShell** (`{{ if eq .chezmoi.os "windows" }}Documents{{ else }}dot_config{{ end }}/PowerShell/aliases.ps1.tmpl`):
    ```gotemplate
    # Auto-generated by chezmoi. DO NOT EDIT.
    {{ range $name, $val := .aliases }}
    {{- if $val.args }}
    function {{ $name }} { {{ $val.cmd }} $args }
    {{- else }}
    function {{ $name }} { {{ $val.cmd }} }
    {{- end }}
    {{- end }}
    ```
  * **Nushell** (`{{ if eq .chezmoi.os "windows" }}AppData/Roaming{{ else }}dot_config{{ end }}/nushell/aliases.nu.tmpl`):
    ```gotemplate
    # Auto-generated by chezmoi. DO NOT EDIT.
    {{ range $name, $val := .aliases }}
    {{- if $val.args }}
    export def --wrapped {{ $name }} [...args] { {{ $val.cmd }} ...$args }
    {{- else }}
    export def {{ $name }} [] { {{ $val.cmd }} }
    {{- end }}
    {{- end }}
    ```

---

### Уровень 2: Кроссплатформенный слой утилит (Nushell Scripts)
Все скрипты автоматизации с нетривиальной логикой (REST API, парсинг JSON/YAML/XML, Kubernetes, Docker, работа с путями) пишутся строго на Nushell (`.nu`) и размещаются в `dot_local/bin/`.

* **Преимущества перед Bash / Batch / PS1:**
  * Кроссплатформенная работа с путями через `path join` без оглядки на слэши (`/` vs `\`).
  * Отказ от утилит `sed`, `awk`, `grep`, `jq`, `curl` благодаря встроенным типам и командам (`http get/post`, `from json`, `to yaml`).
* **Диспетчеризация выполнения в ОС:**
  * **Linux:** Шебанг `#!/usr/bin/env nu`, файл маркируется префиксом `executable_` для Chezmoi (`chmod +x`).
  * **Windows:** Генерация `.cmd`-шиммов для вызова из любых процессов без указания расширения `.nu`:
    `dot_local/bin/{{ if eq .chezmoi.os "windows" }}<script-name>.cmd{{ end }}.tmpl`:
    ```gotemplate
    {{ if eq .chezmoi.os "windows" -}}
    @echo off
    nu "%~dp0\<script-name>.nu" %*
    {{ end -}}
    ```

---

### Уровень 3: Среда и оркестрация задач (`mise` + `just`)

1. **`mise` (Toolchain & Environment):**
   * Декларирует точные версии инструментов в `dot_config/mise/config.toml.tmpl`:
     ```gotemplate
     [tools]
     nushell = "latest"
     just = "latest"
     eza = "latest"
     starship = "latest"
     bat = "latest"
     ripgrep = "latest"
     fd = "latest"

     [env]
     _.path = [
       "{{ .chezmoi.homeDir }}/.local/bin"
     ]
     ```
2. **`just` (Task Runner):**
   * Корневой `Justfile` настраивается на запуск рецептов через Nushell на обеих платформах, полностью исключая конфликт между `cmd.exe` и `/bin/sh`:
     ```just
     set shell := ["nu", "-c"]
     set windows-shell := ["nu", "-c"]

     # Кроссплатформенный рецепт обновления конфигураций
     apply:
         chezmoi apply --source {{ invocation_directory() }}

     # Установка и обновление CLI-тулчейна
     update-tools:
         mise install
         mise upgrade
     ```

## 📊 4. Матрица разделения задач и ограничений

| Задача / Операция | Уровень реализации | Механизм | Ограничения и особенности |
| :--- | :--- | :--- | :--- |
| **Шорткаты (`ll`, `g`, `c`)** | **L1: Shell RC** | Шаблонизация в `chezmoi apply` | Нельзя запускать через `just` во избежание latency. |
| **Навигация (`cd`, прыжки)** | **L1: Shell RC** | Нативные функции (`zoxide init`) | Внешний процесс не может менять `$PWD` родителя. |
| **Экспорт переменных окружения** | **L1 / L3 (`mise`)** | Shell RC-файлы или `mise.toml` | Переменные сессии должны выставляться до старта команд. |
| **Скрипты со сложной логикой** | **L2: Nushell** | Исполняемые `.nu` в `$PATH` | Должны быть чистыми CLI-бинарниками. |
| **Оркестрация задач хоста** | **L3: `just`** | `Justfile` (`nu -c`) | Единый синтаксис Nushell в рецептах для Win/Linux. |
| **Установка CLI-пакетов** | **L3: `mise`** | `mise.toml` | Одинаковые бинарники на всех хостах. |

## 🚀 5. Протокол первичного развертывания (Bootstrap Lifecycle)

Порядок выполнения команд на чистой машине (Linux или Windows):

1. **Развертывание Chezmoi:**
   ```bash
   chezmoi init --apply <git-repo-url>
   ```
   *Раскладывает конфигурации, генерирует `aliases.*`, конфиги `mise` и шиммы скриптов.*

2. **Инициализация тулчейна через Mise:**
   ```bash
   mise install
   ```
   *Устанавливает `nushell`, `just`, `eza`, `starship` и сопутствующие CLI-утилиты.*

3. **Перезапуск терминальной сессии:**
   *Шеллы подключают скомпилированные алиасы и обновленный `$PATH` (`~/.local/bin` и шиммы `mise`).*

4. **Дальнейшая работа:**
   *Все задачи хоста выполняются через `just <recipe>`.*
